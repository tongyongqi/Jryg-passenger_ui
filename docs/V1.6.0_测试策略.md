## 一、需求 → 测试层次映射

### 1.1 需求点 1：网约车车型品类（5 种）

| 车型 code | id | biz_mode | charge_mode | 繁体 | 简体 | 英文 |
|---|---|---|---|---|---|---|
| economy | 1 | 2 | 3 | 經濟型 | 经济型 | Economy |
| preferred | 9 | 2 | 3 | 優選型 | 优选型 | Preferred |
| comfort | 2 | 2 | 3 | 舒適型 | 舒适型 | Comfort |
| business | 3 | 2 | 3 | 商務型 | 商务型 | Business |
| luxury | 4 | 2 | 3 | 豪華型 | 豪华型 | Luxury |

对照出租车：
- chartered_taxi: id=1, biz_mode=1, charge_mode=3（一口价）
- taxi: id=1, biz_mode=1, charge_mode=4（线下打表）, multi_pay_mode=true

**关键点**：网约车与出租车 **id 可相同**（economy id=1 与 chartered_taxi id=1），
唯一键必须是 `code` 或 `id+biz_mode+charge_mode` 组合键。

**可测规则**：
- R1-01 五车型名称三语映射完整且唯一
- R1-02 车型 code 非空唯一
- R1-03 组合键唯一（出租车与网约车同 ID 不互相覆盖）
- R1-04 车型排序 = types 配置顺序
- R1-05 网约车全部为一口价（charge_mode=3）+ 先付
- R1-06 网约车不支持取消费、不支持多退少补
- R1-07 车型列表仅支持单选
- R1-08 出租车/网约车同 ID 时不覆盖

### 1.2 需求点 2/3：预估详情、费用详情、计价规则

- R2-01 预估详情/费用详情/计价规则读取同一计费事实
- R2-02 费项含起步价、里程费、时长费、远途费、合计
- R2-03 计价规则区分 工作日/休息日 × 即时/预约
- R2-04 金额最多 1 位小数，末尾为 0 不显示（如 18.0 → "18"）
- R2-05 计价规则返回 car_type/car_type_name/car_type_img/order_type/order_type_name
- R2-06 rules 结构：day_type/day_type_name/items[{title,desc,value}]
- R2-07 远途费无最大公里时显示"超过n公里"
- R2-08 预约包车费名称调整为"總車費"

### 1.3 需求点 4：车型选择栏三段式高度

- R4-01 三种高度状态：default / expanded / collapsed
- R4-02 expanded 展示起终点，名称最多 10 字，超出用"..."
- R4-03 端展名映射不随高度变化

### 1.4 需求点 5：出发时间入口

- R5-01 入口同首页预约入口共用开关
- R5-02 "現在出發" → 即时业务
- R5-03 选择预约时间 → 预约业务
- R5-04 出发时间实际变化后刷新报价
- R5-05 选项未变化不刷新报价
- R5-06 切换出发时间保留 children/pet 服务偏好

### 1.5 需求点 6：预约规则

- R6-01 预约时间范围：当前时间后 30min ~ 72h
- R6-02 同一乘客仅一笔进行中预约订单
- R6-03 预约与即时互不冲突
- R6-04 预约取消次数与即时独立计算
- R6-05 当日累计取消达 5 次限制新建预约，即时不受影响
- R6-06 既有预约订单仍可取消
- R6-07 预约时间以起点当地时间为准

### 1.6 需求点 7：预约支付与优惠券

- R7-01 包车价士/网约车一口价 → 预付流程
- R7-02 打表的士 → 后付流程
- R7-03 预约全部车型不支持优惠券获取与使用
- R7-04 预约创建携带 coupon_code → passenger-api 拒绝
- R7-05 order-service 预约创建及锁券前再次拒绝
- R7-06 即时网约车优惠券与即时出租车一致
- R7-07 即时网约车未登录/预估详情/费用详情沿用即时出租车优惠口径
- R7-08 预约报价不调用优惠券匹配

### 1.7 需求点 8：呼叫与取消

- R8-01 预约呼叫超时采用派单侧"出发时间前 10 分钟"规则
- R8-02 预付订单取消页增加"已支付款項將按原有途徑退還至您的帳戶"
- R8-03 非预付订单无该提示

### 1.8 需求点 9：预约接单后履约状态机

- R9-01 新增待服务状态（100 司机已接单）
- R9-02 司机侧开始接驾 → 接驾状态
- R9-03 距出发时间 > 20min 不下发司机位置
- R9-04 进入出发前 20min 后展示司机位置及接驾路线
- R9-05 后续状态复用即时展示 + "預約用車"标签
- R9-06 取消次数与即时独立

### 1.9 需求点 10：一口价弹框与消息栏

- R10-01 一口价订单接单后展示一口价提醒弹框
- R10-02 消息1（纸质发票）仅出租车车型展示
- R10-03 消息2（一口价附加费）全部一口价订单展示
- R10-04 多条消息 3 秒间隔轮播
- R10-05 消息2 文案为"本單為一口價..."
- R10-06 一口价说明弹框内容

### 1.10 需求点 11/12：预约通知、安全、分享

- R11-01 预约安全中心、评价、短信、收据
- R11-02 司机接单用新增预约模板
- R11-03 司机取消/行程结束复用即时模板

- R-D-11 取消统计开关 false 时完全跳过

## 二、实现策略

### 2.1 三层架构（沿用 V1.5.0 范式）

```
passenger_android_core/v160/
├── contract.py     # 纯内存契约模型（离线可测）
├── device_steps.py # 真机步骤（UI 操作 + 接口日志抓取 + DB 直查）
├── api_log.py      # 复用 v150 的接口日志解析（可继承）
└── db_verify.py    # 复用 v150 的 PolarDB 直查

cases/passenger_v1_6_0/
├── test_v160_car_type_offline.py      # 车型品类
├── test_v160_estimate_offline.py      # 报价/预估详情/计价规则
├── test_v160_booking_offline.py       # 预约规则/下单分流/取消限制
├── test_v160_coupon_offline.py        # 优惠券口径
├── test_v160_fulfillment_offline.py   # 履约状态机/司机位置暴露
├── test_v160_share_offline.py         # 分享/安全/通知
├── test_v160_api_contract_offline.py  # 接口出入参契约
├── JRYG_test_android_v160_booking.py       # 真机：预约链路
├── JRYG_test_android_v160_ride_hailing.py  # 真机：网约车即时
└── test_v160_order_center_db.py            # DB 直查
```

### 2.2 命名与风格约定（与 v150 保持一致）

- 契约函数：纯函数，参数显式，返回 dict 或 (bool, str) 或 raise ValueError
- 设备步骤：`v160_xxx` 前缀
- 用例文件：真机 `JRYG_test_android_v160_*.py`；离线 `test_v160_*_offline.py`
- 真机类继承 `V160DeviceSteps`，`__test__ = True`
- 环境不满足用 `pytest.skip`

### 2.3 优先级

| 优先级 | 模块 | 理由 |
|---|---|---|
| P0 | 车型品类、预约规则、优惠券口径、下单分流 | 核心业务规则，风险最高 |
| P0 | 计费明细/计价规则 | 新增页面与接口 |
| P1 | 履约状态机、司机位置暴露 | 依赖真实派单，验证成本高 |
| P1 | 分享/安全/通知 | 依赖订单状态 |
| P2 | 车辆图片颜色适配 | 依赖司机侧数据 |
| P2 | 接口出入参契约 | 可离线 mock 验证 |

### 3.2 契约层发现并修正的设计缺陷

1. **订单状态机无法区分「待支付」与「已支付」**
   原始 `resolve_booking_status` 用同一个 `paid_at` 参数表达两个状态，
   导致 105（待支付）永远无法命中。已拆分为 `unpaid_at` + `paid_at`。

2. **「我的行程」分组与 PRD 不符**
   PRD 明确「已接单待接驾态展示为待服务」，接驾后即进入「服务中」。
   原实现把 101（接驾）/102（到达起点）归入待服务，已修正。

3. **车型栏高度状态与端展名映射缺口**
   PRD 要求端展名映射（`經濟型`/`经济型`/`Economy`），补充了
   `CAR_TYPE_NAMES` 三语映射与 `localize_car_type()`。
